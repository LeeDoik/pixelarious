# LAST LOGIN (마지막 접속) — 게임 디자인 스펙

작성일: 2026-08-13
상태: 사용자 검토 대기
플랫폼: NEO_KIDO 첫 번째 정식 카트리지 (사이트 스펙: `2026-08-13-neo-kido-design.md`)

## 1. 개요

**LAST LOGIN (마지막 접속)** — 주워온 낡은 컴퓨터 속을 뒤지며 전 주인의 실종을 추적하는 데스크톱 호러 어드벤처.

- **로그라인**: "2003년 겨울, 재활용 수거장에서 주워온 컴퓨터. 전원을 켜자 3개월 전에 멈춘 한 사람의 삶이 부팅된다."
- **목적**: 포트폴리오 대표작. 분위기·연출로 기억되는 게임. NEO_KIDO의 첫 진짜 게임으로서 "만들다 → 올리다 → 플레이되다" 전체 파이프라인을 실증하고 Phase 2 진입 조건을 충족시킨다.
- **분량**: 한 자리 30–45분 완주형. 싱글 엔딩 + 숨겨진 엔딩 1개.
- **장르 계보**: Her Story·Simulacra·Hypnospace Outlaw 계열의 "발견된 기기(found device)" 서사 — 단, 한국 2000년대 초 인터넷 문화라는 미개척 소재로 차별화.

## 2. 스토리·세계관

### 2.1 배경

한국, 2003년 2월(실종 3개월 후). 플레이어는 퇴근길 재활용 수거장에서 낡은 컴퓨터 본체를 주워 집에서 켠다. 화면에 뜨는 것은 "누리OS 2002" — 그리고 3개월 전 어느 날 멈춘 한 사람의 흔적.

### 2.2 인물

| 인물 | 설정 |
|---|---|
| **한성진 (27)** | 컴퓨터의 전 주인. 공무원 시험 준비생. 2001년부터 반복된 낙방으로 고립 → 인터넷 카페에서 자기계발 모임으로 위장한 사이비 종교 **"새빛수련회"**에 빠짐 → 헌금·절교·교리 필사 → 탈퇴 시도와 협박 → **2002년 11월 실종**. 게임 내내 파일로만 존재한다. |
| **한슬기** | 성진의 동생. 오빠를 찾고 있다. 컴퓨터가 켜지자 메신저로 말을 걸어온다. **플레이어의 대화 상대이자 힌트 창구.** |
| **새빛수련회** | 가상의 사이비 종교 단체. 자기계발·마음수련으로 위장해 온라인 카페로 포교. 직접 등장하지 않고 문서·메일·캐시 페이지로만 실체가 드러난다. |

### 2.3 서사 원칙

- 공포는 **기록의 내용**에서 나온다. OS는 끝까지 정상 작동한다 — 글리치·점프스케어·가짜 오류 연출 없음.
- 성진이 빠져드는 과정을 3단계(일상 → 심취 → 탈출 시도)로 보여주되, 플레이어가 파일을 여는 순서로 스스로 재구성하게 한다.
- 폭력·자해의 직접 묘사 없음. 협박과 불안은 암시로 처리한다. (수위 기준: 15세 내외)

### 2.4 엔딩

- **본편 엔딩**: 휴지통에서 복원한 마지막 기록으로 성진의 행방 단서(수련원 위치·증거)를 슬기에게 전달한다. 성진을 직접 구하는 장면은 보여주지 않는 절제된 결말.
- **숨겨진 엔딩**: 지정된 **기록물 9개**를 전부 열람한 플레이어만, 엔딩 후 추가 신을 본다 — 컴퓨터는 성진이 버린 것이 아니라 **교단이 증거인멸로 버린 것**이었다는 사실이 드러나고, 메신저에 낯선 계정이 접속한다: "그 컴퓨터, 어디서 나셨어요?"

## 3. 플레이 구조

### 3.1 액트 구성 (합계 30–45분)

| 액트 | 분량 | 내용 |
|---|---|---|
| **Act 0 · 부팅** | ~2분 | 전원 버튼 → POST/부팅 로고(엔진 로딩을 겸함) → 바탕화면. 튜토리얼 없이 자유 탐색. |
| **Act 1 · 호기심** | ~10분 | 일상 파일(낙방 수기, 가족사진) → 메신저에 슬기 접속 이벤트 → **퍼즐 1**. |
| **Act 2 · 위화감** | ~15분 | 수련회 폴더 개방 — 입금내역, 절교 채팅로그, 교리 필사 → **퍼즐 2, 3**. |
| **Act 3 · 진실** | ~10분 | **퍼즐 4** → 마지막 일기 + 수련원 위치 → 슬기에게 전달 → 엔딩. |

### 3.2 퍼즐 4개

| # | 퍼즐 | 답의 출처 |
|---|---|---|
| 1 | 잠긴 폴더의 비밀번호 (영숫자) | 미니홈피 게시글 속 날짜 |
| 2 | 암호 걸린 이메일 첨부 압축파일 | 교리 필사 문서 속 상징 숫자 |
| 3 | 폐쇄된 수련회 카페의 캐시 페이지 접근 | 즐겨찾기 + 이메일 속 주소 조합 |
| 4 | 휴지통에서 지워진 기록 복원 | Act 1–3에서 수집한 단서로 복원 대상 특정 |

정답의 구체 값은 콘텐츠 데이터(§7)에서 정의한다. 스펙 차원의 규칙:

- **모든 답은 컴퓨터 안에 있다** — 외부 검색·실제 인터넷 불필요.
- **입력은 영숫자만** — 한글 IME 리스크 제거, 2002년 비밀번호 감성과도 일치. 대화는 전부 선택지 클릭.
- **힌트 시스템**: 같은 게이트에서 5분간 진전이 없으면 슬기가 먼저 말을 걸어 힌트를 제공. 이후 3분 간격으로 단계 상승 — 3단계(방향 → 위치 → 답 직전).
- **진행 게이트는 플래그 기반** — 특정 파일 열람·비번 해제·대화 완료가 다음 이벤트를 연다.

## 4. 가짜 OS 명세 — "누리OS 2002"

- XP 시대 디자인 언어(청록 작업표시줄, 그라데이션 타이틀바, 베이지 모니터 베젤)를 쓰되, **이름·로고는 전부 가상** — 실존 브랜드(Windows, XP, Luna, 시작 버튼 원형) 모사 금지. NEO_KIDO의 "리프하되 실명은 쓰지 않는다" 원칙과 동일. 상표·트레이드 드레스 리스크 차단.
- 가상 브랜드 패밀리: OS **누리OS 2002**, 이메일 **누리메일**, 브라우저 **누리서퍼**, 메신저 **단짝**(버디버디풍), 미니홈피 **마이홈**(싸이월드풍), PC 본체 **한별컴퓨터**.
- 게임 화면 = 4:3 모니터 한 대. **해상도 1024×768 고정**, 브라우저에서 레터박스 스케일.

### 설치된 프로그램 (각각이 게임의 "방")

| 프로그램 | 모델 | 역할 |
|---|---|---|
| 파일 탐색기 + 사진 뷰어 | 내 문서 | 일기·이력서·필사 문서·디카 사진. 스토리의 몸통 |
| 메신저 "단짝" | 버디버디 | 슬기와 실시간 대화(선택지) + 과거 대화 로그. 힌트 창구 |
| 이메일 "누리메일" | 한메일 | 헌금 요구 메일, 암호 첨부파일, 시대감성 스팸(복선 겸용) |
| 브라우저 "누리서퍼" | IE6 | 즐겨찾기, 폐쇄된 카페(캐시 열람), 성진의 미니홈피 |
| 휴지통 | — | Act 3 핵심 — 지워진 마지막 기록 복원 |
| 메모장·그림판 | — | 소품. 열어보면 소소한 복선 |

## 5. 연출

- **부팅 화면이 로딩 화면을 겸한다** — wasm 로딩 시간을 "낡은 컴퓨터가 부팅되는 연출"로 흡수.
- CRT 느낌은 미세한 스캔라인+비네트 셰이더 1장. 과하지 않게 — OS는 끝까지 "정상"이어야 한다.
- **사운드가 공포의 주력**: 컴퓨터 팬·형광등 험 앰비언트 위에 액트가 진행될수록 낮은 드론이 한 겹씩 추가. 메신저 알림음은 처음엔 반갑고 나중엔 긴장되는 소리로 기능이 바뀐다. 음악은 엔딩 1곡으로 최소화.
- 시계·창밖 소리 등 미세한 시간 경과 연출(저녁 → 새벽).

## 6. 에셋 계획

| 카테고리 | 물량 | 조달 방법 |
|---|---|---|
| **텍스트 콘텐츠** | 문서 40–60개 (일기·이메일·채팅로그·교리 문서·미니홈피 글) | **최대 물량이자 게임의 본체.** Claude가 스토리 골격에 맞춰 초안 작성 → 사용자 검토·수정. 전부 JSON 데이터로 구현과 분리 |
| UI 스킨 | 창·버튼·작업표시줄 | 이미지 거의 불필요 — Godot Theme + StyleBoxFlat(그라데이션·베벨을 코드로 정의) |
| 픽셀 아이콘 | 20–30개 | 스크립트 절차 생성(사이트 커버 아트와 같은 방식) 또는 AI 생성 후 다듬기 |
| 사진 | 10–15장 | AI 이미지 생성 → **2000년대 디카 화질로 열화 처리**(640×480 축소, 노이즈, JPEG 아티팩트 — 열화가 AI 티를 지워줌). 실존 인물 사진 금지 |
| 폰트 | 한글 비트맵 1–2종 | 네오둥근모(사이트에서 이미 자체 호스팅) 또는 갈무리(Galmuri) — 무료, 시대 감성 적합. 실제 굴림체는 MS 라이선스라 배제 |
| 사운드 | SFX·앰비언트 15–20개 + 엔딩곡 1 | CC0(freesound) + AI 사운드 생성 + 신디사이징 조합 |

**라이선스 원칙**: 모든 에셋은 자작·AI 생성·CC0 중 하나로만 조달하고 `CREDITS.md`에 출처를 기록한다. 유료 에셋 구매 없음 — 포트폴리오 공개 배포에 법적 걸림돌 제로.

## 7. 기술 설계

- **엔진: Godot 4.3+ Standard 버전(GDScript)**. .NET(C#) 버전은 웹 익스포트를 지원하지 않으므로 배제. 웹 익스포트는 스레드 비활성화(사이트 스펙대로 COOP/COEP 헤더 불필요).
- **씬 구조**: `Boot`(부팅 연출) → `Desktop`(바탕화면 + 창 관리자) → 각 프로그램은 독립 씬(탐색기·메신저·메일·브라우저·휴지통). 창 관리자는 드래그·z-order·작업표시줄 버튼을 Control 노드로 구현.
- **스킨은 Theme 리소스 하나로 통일** — 스킨 수정이 한 곳에서 끝난다.
- **콘텐츠는 데이터, 코드는 뼈대**: 파일 트리, 문서 내용, 채팅 스크립트, 이메일, 퍼즐 정답, 플래그 조건 전부 JSON. 시나리오 수정에 코드 수정이 필요 없고, 영어판은 데이터 교체로 해결(구조만 준비, 번역은 범위 외).
- **저장**: 플래그 딕셔너리 하나로 진행 상태 관리, `user://`에 자동저장(웹에서는 IndexedDB로 유지 — 창을 닫아도 이어하기 가능).
- **작업 방식**: Godot 프로젝트는 전부 텍스트 파일(.tscn/.gd/.tres/project.godot)이므로 Claude가 파일 도구로 직접 작성·수정한다. 임포트·테스트·웹 익스포트는 `godot --headless` CLI로 실행. 사용자의 역할은 에디터·브라우저에서 열어보고 느낌을 판단하는 것.

## 8. 플랫폼 통합 (NEO_KIDO)

- 웹 익스포트 결과물: `public/games/last-login/` (Vercel 파일당 100MB 한도 내 — wasm+pck 예상 30–40MB로 여유).
- 게임 레코드: `content/games/last-login.json` — 기존 카트리지·iframe 임베드 패턴에 그대로 꽂힌다.
- 카트리지 표기: **LAST LOGIN** + 한글 부제 **마지막 접속**. 태그에 "MOUSE REQUIRED" 포함 — 데스크톱 우선, 모바일은 실행되되 최적화는 후순위.

## 9. 검증

- **로직 단위 테스트(gdUnit4)**: 퍼즐 정답 판정, 플래그 게이트 조건, 기록물 9개 카운트와 숨겨진 엔딩 발동, 힌트 단계 진행.
- **웹 익스포트 스모크 테스트**: 로드 → 저장 → 이어하기 → 전체 클리어가 브라우저에서 통과.
- **플레이테스트 체크리스트**: 완주 30–45분 타깃 확인, 퍼즐별 막힘 지점 기록, 힌트 발동 타이밍 점검.

## 10. 범위 제외

- 멀티 엔딩 분기(숨겨진 엔딩 1개만), 영어판(데이터 구조만 준비), 모바일 최적화, 실제 인터넷 연결 연출, 글리치·메타 호러 연출, 음성·컷신.
