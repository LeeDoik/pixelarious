# BEAT SHIFT — 게임 설계

**날짜:** 2026-08-22
**상태:** 사용자 질답으로 확정된 설계 (구현 플랜의 입력)
**대상:** PIXELARIOUS 신규 카트리지 `beat-shift` (개발 중에는 hidden)

## 1. 컨셉

노트 하이웨이 없이 **픽셀 장면 자체가 큐가 되는 원버튼 리듬 메들리** (리듬세상 계열).

- 장면 속 캐릭터의 예비 동작과 예비음이 신호, 정박에 탭 하나로 응답한다
- 4개 장면이 돌아가며 무한 반복되는 **엔드리스 메들리 스코어 어택** — 바퀴를 돌 때마다 템포·난도 상승
- 그래픽이 주인공: 판정선·노트·게이지 숫자 같은 추상 UI를 최소화하고, 픽셀 연출이 게임 상태를 말한다
- 프레임 서사는 없음(순수 메들리). 추후 "밤샘 알바" 프레임을 붙일 수 있는 여지는 남긴다 — 제목 BEAT SHIFT는 그때도 유효

## 2. 장면 4종 (라운드)

| # | 장면 | 탭 = 행동 | 큐를 주는 배우 | 주조색 | 성공음 악기 |
|---|---|---|---|---|---|
| 1 | 대장간 망치질 | 달군 쇠를 망치로 때림 | 조수가 쇠를 모루에 올림 | 주황/불티 | 금속 벨 |
| 2 | 야밤 포장마차 | 날아오는 재료를 웍으로 받음 | 손님(들)이 재료를 던짐 | 네온 핑크 | 플럭/뽕 |
| 3 | 우주선 정비 도크 | 컨베이어 부품을 망치로 조립 | 컨베이어가 부품을 운반 | 시안 | 사각파 블립 |
| 4 | 픽셀 밴드 무대 | 드럼을 침 | 밴드 멤버들의 연주 프레이즈 | 보라/조명 | 스네어+킥 |

- 모든 장면은 **탭 단일 입력**(터치 아무 데나 / Space / 좌클릭) — 홀드·스와이프 없음
- 큐 규칙 공통: 정박 **2박 전에 예비 동작 + 예비음** 시작 (예: 조수가 쇠를 들어올리는 모션 + "칭" 예비음). 장면이 달라도 리듬 문법은 동일해 학습이 이전된다
- 각 장면은 공통 인터페이스를 구현하는 독립 Godot 씬 — 컨덕터로부터 패턴 이벤트를 받아 배우 애니메이션과 판정 타이밍을 구동

## 3. 코어 루프

1. 장면 시작 → 배우가 패턴대로 큐를 보냄
2. 탭 판정: **PERFECT ±70ms / GOOD ±140ms / 그 외·미입력 MISS** (시작값, 플레이테스트로 튜닝. 모바일 웹 레이턴시를 감안해 넉넉하게 시작)
3. 한 장면 = **8마디(패턴 4개)** → 1마디 전환 징글과 함께 다음 장면으로 교대
4. 4장면 = 1루프. 루프마다 **BPM 96 → 112 → 128 → 144 → 160(상한)**, 패턴 난도 티어도 상승
5. 게임오버 → 슬로모+픽셀 연출(0.5s) → SCORE/BEST → 탭 한 번으로 재시작 (2초 이내)

## 4. 그루브 게이지 (게임오버 규칙)

- 시작 60%. **PERFECT +4 / GOOD +2 / MISS −15** (튜닝 대상)
- 0%가 되면 게임오버. 장면 전환 성공 시 +10 회복
- 표시는 숫자 게이지가 아니라 **픽셀 VU미터** — 그루브가 높으면 장면 연출도 살아남(불꽃이 커지고, 손님이 늘고, 조명이 화려해짐), 낮으면 장면이 시들해짐. 게이지 자체가 그래픽 연출

## 5. 스코어링

- PERFECT 100점 / GOOD 50점
- 연속 PERFECT·GOOD 콤보 배수 **×2…×5 상한** (MISS 시 리셋 — STARFALL DRIFT 스위프트 호핑과 동일 문법)
- 루프 완주 보너스 +500 × 루프 수
- 최종 점수 합산, 로컬 베스트 `user://` 저장(웹 IndexedDB 영속)

## 6. 음악 — 미니멀 퍼커션 방식

- 배경음악은 **드럼·베이스 루프만** 최소한으로 깔고, 플레이어의 탭 성공음(장면별 악기)이 멜로디를 완성한다 — 잘 칠수록 음악이 풍성해지는 리듬세상 정공법
- MISS는 음이 비거나 탁한 실패음 — 소리만으로 잘하고 있는지 안다
- 제작: `scripts/gen_audio.py` 확장(파이썬 합성 칩튠). 장면별 퍼커션 루프를 **BPM 단계별 사전 렌더링** — 4장면 × 5단계 = 짧은 루프 20개 + 성공음/실패음/예비음/징글 원샷. 용량 부담 미미
- SFX: 탭 성공음(장면×판정 등급), 예비음, MISS음, 장면 전환 징글, 게임오버, 베스트 갱신

## 7. 리듬 엔진 (기술 핵심·최대 리스크)

- **컨덕터 패턴**: 박자 시계는 `AudioStreamPlayer.get_playback_position() + AudioServer.get_time_since_last_mix() − AudioServer.get_output_latency()`로 구동. 시각 프레임이 아니라 오디오 시계가 진실
- 판정·패턴·게이지·스코어 로직은 `src/core/` 순수 함수로 분리 (gdUnit4 헤드리스 테스트 대상):
  - `conductor_math.gd` — 오디오 시각 → 비트 변환, 판정창 계산
  - `patterns.gd` — 장면별 패턴 데이터(비트 단위)와 난도 티어 선택
  - `groove.gd` — 게이지 증감·게임오버 판정
  - `scoring.gd` — 판정 등급 → 점수·콤보 배수
- 패턴은 코드가 아니라 **데이터(비트 오프셋 배열)** — 장면 추가·난도 조정이 데이터 작업이 되도록
- **리스크: 모바일 웹 오디오 레이턴시.** 대응: ① 판정창을 넉넉히 시작 ② 전 판정에 적용되는 전역 입력 오프셋 상수(플랫폼별 튜닝) ③ 실기 플레이테스트로 조정. 수동 캘리브레이션 화면은 1단계에서 만들지 않음(YAGNI — 플레이테스트에서 필요가 확인되면 추가)

## 8. 세션 흐름과 UI

- 타이틀: 로고 + "TAP TO GROOVE" — 첫 장면 첫 패턴이 곧 튜토리얼(느린 BPM 96, 단순 정박)
- 플레이 HUD: 픽셀 VU미터(그루브)와 콤보 배수만. 점수는 장면 전환 때 잠깐 표기 — 최소주의
- 게임오버: SCORE / BEST / "TAP TO RETRY"
- 포커스 잃으면 자동 일시정지(PAUSED 오버레이, 탭 재개) — 재개 시 현재 마디 처음부터 다시(박자 어긋남 방지)
- UI 라벨은 영어 아케이드 관용구, 폰트 Galmuri

## 9. 비주얼

- 기준 뷰포트 **270×480 (9:16 세로)**, `canvas_items` 스트레치 — STARFALL DRIFT와 동일
- 장면마다 뚜렷한 주조색(§2 표)으로 전환이 한눈에 보이게. 전환은 1마디 동안 픽셀 와이프/암전
- **에셋은 PixelLab 생성 우선** 후 팔레트 후처리 (STARFALL DRIFT 파이프라인 재사용, `PIXELLAB_API_KEY`): 주인공(장면별 행동 모션), 장면별 배우·소품·배경, 타이틀 로고, 커버 아트
- 판정 피드백은 텍스트가 아니라 연출: PERFECT = 불티/광채 파티클 + 화면 미세 펀치, GOOD = 작은 파티클, MISS = 배우 휘청·연기

## 10. 기술 아키텍처

- 신규 `games-src/beat-shift/` — Godot 4.7.1 Standard(GDScript), gdUnit4 하네스 동일 패턴(`$GODOT = C:\Users\LeeDoik\tools\godot\godot_console.exe`)
- 오토로드: `GameState`(점수/베스트/세션), `Sfx`(사운드), `Conductor`(박자 시계)
- 씬: `Main`(타이틀→플레이→게임오버 상태 머신), `SceneStage`(장면 공통 베이스) + 장면 4종, `Hud`
- 물리 엔진 미사용. 웹 익스포트: Web 프리셋, 스레드 비활성화, `web/shell.html` 재사용, export_path `../../public/games/beat-shift/index.html`
- 사이트 등록: `content/games/04-beat-shift.json` — `"hidden": true`로 시작(런칭 시 해제), 태그 `GODOT 4`/`2D`/`RHYTHM`/`ONE BUTTON`/`MOBILE`/`PC`, coverScene·coverImage는 커버 제작 단계에서

## 11. 단계별 구현 (사용자 확정)

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 1 | 리듬 엔진 + **대장간** 단일 장면 엔드리스 (템포 상승 포함) | 단일 장면만으로 완결·배포 가능, 코어 테스트 통과 |
| 2 | **포장마차** 추가 → 2장면 메들리 + 전환 시스템 | 전환 징글·게이지 회복 동작 |
| 3 | **정비 도크** 추가 → 3장면 메들리 | 장면 추가가 데이터+씬 작업만으로 되는지 검증 |
| 4 | **밴드 무대** 추가 → 완전체 4장면 메들리, hidden 해제 검토 | 전체 플레이테스트 통과 |

각 단계는 독립적으로 배포 가능한 상태로 끝낸다.

## 12. 테스트 전략

- gdUnit4 단위 테스트(헤드리스): `conductor_math`(비트 변환·판정창 경계), `patterns`(난도 티어별 패턴 선택·비트 정렬), `groove`(증감·게임오버 경계), `scoring`(콤보 배수·리셋)
- 사이트 vitest 기존 스위트 통과(games.ts 스키마)
- 수동 플레이테스트 체크리스트: `docs/superpowers/specs/beat-shift-playtest.md` (구현 단계에서 작성) — 데스크톱 크롬/파이어폭스 + 모바일 크롬/사파리 실기, **체감 판정 싱크**·30fps 이상·재시작 루프·베스트 영속

## 13. 성공 기준

- 모바일 브라우저에서 터치만으로 온전히 플레이 가능, 판정이 "억울하지 않다"고 느껴질 것
- 첫 판에서 설명 없이 큐 문법을 이해 (2박 예비 규칙)
- 죽음→재시작 2초 이내, gdUnit4·vitest 전부 통과, 프로덕션 카트리지 PLAY 동작

## 14. 하지 않는 것 (YAGNI)

- 스테이지 선택 모드·랭크 시스템 (엔드리스 메들리 단일 모드)
- 홀드·스와이프·멀티터치 입력 (탭 단일)
- 멜로디 BGM·보컬 (미니멀 퍼커션 확정)
- 수동 레이턴시 캘리브레이션 화면 (플레이테스트에서 필요 확인 시 추가)
- 서버 리더보드, 게임패드, PWA 오프라인
- 프레임 서사 (추후 "밤샘 알바" 프레임 추가 여지만 남김)
