# NEO_KIDO — 게임 배포 포트폴리오 사이트 디자인 스펙

작성일: 2026-08-13
상태: 사용자 검토 대기
디자인 목업: https://claude.ai/code/artifact/78a9e174-cc9e-48bb-9787-226334822b2d
(목업 소스: 같은 폴더의 `2026-08-13-neo-kido-mockup.html` — 구현 시 이 파일이 시각적 기준)

## 1. 개요와 목적

NEO_KIDO는 1인 게임 개발자 LeeDoik이 만든 게임을 배포하는 개인 사이트다. itch.io처럼 게임을 나열하고 브라우저에서 바로 플레이하게 하되, **포트폴리오 성격이 강하다** — 게임과 함께 "누가 만들었는지"가 기억에 남아야 한다.

- 독자(모두 해당): 글로벌 인디 게임 커뮤니티, 일반 플레이어, 외주/협업 의뢰인, 국내 게임사 채용 담당자
- 성공 기준: 방문자가 게임을 바로 플레이할 수 있고, 개발자에게 연락할 방법을 쉽게 찾으며, 사이트 자체가 픽셀 감성의 작품으로 기억됨

## 2. 브랜드

- 사이트 이름: **NEO_KIDO** (언더스코어 포함 표기가 정식)
- 이름 계보: 레트로 게임기(네오지오 등) 이름 문법의 리프. 실존 브랜드명 직접 사용은 하지 않음
- 도메인 후보: `neokido.games`(1순위), `neokido.io`, `neo-kido.com` — 2026-08-13 DNS 조회 기준 미등록 추정, 구매는 보류 상태. 구매 전까지 Vercel 기본 도메인 사용
- 로고: 별도 로고 없음. 픽셀 폰트로 타이핑되는 이름 자체가 로고

## 3. 비주얼 시스템

### 3.1 팔레트 — 2종, 방문자가 전환

**NIGHT (기본)** — PICO-8 계열 아케이드 무드:

| 토큰 | 값 | 용도 |
|---|---|---|
| bg | `#141127` | 페이지 배경 |
| bg-deep | `#0C0A1C` | 하드 섀도, 커버 하늘 |
| surface | `#1D2B53` | 카트리지/박스 배경 |
| text | `#FFF1E8` | 본문, 프레임(테두리) |
| dim | `#8E99D9` | 보조 텍스트, 태그 |
| accent | `#FF77A8` | 포인트(마젠타), 선택 영역 |
| accent2 | `#29ADFF` | 배지(시안) |
| gold | `#FFEC27` | 커서, 언더스코어, PLAY 버튼, 화살표 |

NIGHT에만 CRT 스캔라인 오버레이(3px 반복 그라데이션, 검정 16%)를 얹는다.

**DMG** — 게임보이 오리지널 4색을 엄격하게 유지: `#081820`(잉크) / `#346856`(미드) / `#88C070`(리프) / `#E0F8D0`(페일). 스캔라인 없음.

- 테마 토글은 **사이트의 정식 기능**: 우상단 고정 "PALETTE" 버튼, 선택은 localStorage에 저장되어 재방문 시 유지
- 모든 색은 CSS 변수로만 사용한다. 새 UI 요소는 두 팔레트 모두에서 검증
- 커버 아트도 팔레트에 맞춰 다시 그린다(팔레트 스왑 오마주)
- 향후 3번째 팔레트 추가 가능성 열어둠(버튼 순환식 전환). 초기 출시는 2종

### 3.2 타이포그래피

- 디스플레이(영문): **Press Start 2P** — 사이트 이름, 섹션 제목, 게임 제목, 버튼
- 본문(한글 포함): **네오둥근모(NeoDunggeunmo)** — 설명, 태그, 보조 텍스트. 한글 11,172자 전체 커버 확인됨
- 두 폰트 모두 woff2 자체 호스팅(외부 CDN 의존 금지). 합계 약 51KB로 가벼움
- 본문 기본 17px / 행간 1.75, 게임 설명은 최대 60ch

### 3.3 픽셀 미학 규칙

- `border-radius` 금지(모서리는 각지게), 테두리 3–4px 단색
- 그림자는 블러 없는 하드 섀도(`8px 8px 0`), 버튼 누름은 translate+섀도 축소로 표현
- 래스터 이미지·캔버스는 `image-rendering: pixelated`
- 등장/전환 효과는 `steps()` 타이밍(예: 커서 깜빡임, 화살표 바운스). 단, **카트리지 확장은 예외로 부드럽게**(사용자 결정): `0.45s cubic-bezier(.22,.9,.3,1)`

## 4. 페이지 구조 (단일 페이지)

### 4.1 히어로 — 풀뷰포트
- `NEO_KIDO`가 한 글자씩 타이핑(글자당 95ms, 시작 전 600ms 대기), 골드 블록 커서(█) 1s 깜빡임
- 타이핑 완료 시 언더스코어(_)가 골드로 변함
- 타이틀 외 문구 없음(태그라인 제거됨 — 사용자 결정)
- 하단 중앙 "SCROLL TO SELECT" + 골드 ▼ 바운스, 15px
- 타이틀 크기 `clamp(28px, 8vw, 76px)`

### 4.2 SELECT GAME — 카트리지 배너 목록
- 섹션 제목 "► SELECT GAME", 부제 "Hover a cartridge to open it — tap on mobile."
- 게임당 가로 배너(카트리지) 1개, 세로 스택, 간격 28px
- 접힌 상태: 번호(01…) + 커버(200×84px) + 게임 제목(+한글 부제) + "▼ OPEN"
- 확장(호버 또는 탭): 커버 150px로 성장, 점선 구분선 아래 설명·태그·"▶ PLAY" 버튼(골드) 표시
- 마지막 슬롯은 "EMPTY SLOT / NEW GAME +" 빈 상태(점선 테두리) — 다음 게임 예고
- 커버 아트: 게임별 스틸이 준비되기 전까지 시드 기반 절차적 캔버스 픽셀 아트

### 4.3 PLAYER 1 — 개발자 소개
- 소개 문단(개발자 정체성, 사용 엔진, 협업 환영) + GITHUB / ITCH.IO / EMAIL 픽셀 버튼 + 배지(ENGINE: GODOT 4, NEXT: UNITY 3D 등)
- 실제 링크 URL은 구현 시 확정. 준비 안 된 링크는 버튼 자체를 표시하지 않음(죽은 링크 금지)

### 4.4 푸터
- "© 2026 NEO_KIDO · 모든 게임은 무료로 플레이할 수 있습니다" + "INSERT COIN ●"(골드)

## 5. 인터랙션 규칙

- **호버 확장은 `@media (hover:hover) and (pointer:fine)`에서만** 작동 — 터치 기기의 sticky-hover로 배너가 안 닫히는 버그 방지(모바일 실기기 검증 완료)
- 터치/클릭: 스트립 탭 → `.open` 토글, `aria-expanded` 동기화
- 키보드: 스트립 `tabindex=0`, Enter/Space로 토글, `:focus-visible`에 점선 아웃라인
- `prefers-reduced-motion: reduce`: 타이핑 즉시 완료, 바운스·확장 트랜지션 제거
- 모바일(≤640px): 카트리지가 제목 위/커버 아래 2행 구조로 재배치, 커버 가로 100%

## 6. 콘텐츠·언어 정책

- UI 라벨은 영어(SELECT GAME, PLAYER 1, OPEN, PLAY 등 아케이드 관용구)
- 게임 설명·소개 문단은 한국어. 영어 병기는 게임별 선택 사항으로 시작(글로벌 반응이 생기면 확대)
- 현재 게임 3종(STARFALL DRIFT, DOWN THE CAVE, PIXEL PONG.EXE)과 소개 문구는 **레이아웃 검증용 플레이스홀더** — 실제 게임 등록 시 교체

## 7. 기술 방향 (구현 계획의 입력)

- 게임 제작: Godot 4.3+ 웹 익스포트, 스레드 비활성화 옵션(COOP/COEP 헤더 불필요) 기본
- 호스팅: Vercel(무료 Hobby로 시작, 파일당 100MB 한도 내). 사이트와 게임 파일 동일 배포
- 확장: Unity WebGL(3D) 추가 시 게임 파일만 Cloudflare R2 분리 검토
- 사이트 본체는 **Next.js 앱**(정적 생성 우선) — Phase 2(§9)에서 인증·업로드 API를 같은 앱에 붙이기 위한 선택
- **게임 = 데이터 레코드**: 카트리지 목록은 메타데이터(제목, 설명, 태그, 커버, 파일 경로)에서 렌더링. Phase 1은 JSON/파일 기반, Phase 2에서 DB로 교체해도 UI 불변
- **게임 실행은 iframe 임베드 패턴**: 본인 게임도 외부 게임과 동일한 방식으로 실행 — Phase 2에서 샌드박스 적용 시 구조 변경 없음

## 8. 이번 범위에서 제외

- 회원가입·댓글·평점, 다국어 전환 UI, 게임 검색/필터(게임 수가 적음), 데브로그/블로그, 3번째 팔레트
- 외부 크리에이터 업로드 — §9 로드맵으로 명시적 연기

## 9. 확장 로드맵 — Phase 2: 외부 크리에이터 업로드 (별도 스펙으로 진행)

**비전**: 간단한 아이디어만 있으면 누구나 NEO_KIDO에 게임을 바로 올릴 수 있는 플랫폼.

Phase 2에서 필요한 것 (이번 구현 범위 아님):
- 회원 인증 + 게임 메타데이터 DB + 파일 저장소 — Supabase(무료 티어 시작)가 1순위 후보
- 업로드 플로우: zip 업로드 → 검증(index.html 존재, 용량 제한) → 자동 게시
- 보안: 외부 게임은 반드시 샌드박스된 iframe에서 실행(별도 오리진 권장), XSS/피싱 대비
- 운영: 신고/삭제 등 최소한의 모더레이션 수단
- 비용 재검토: 외부 콘텐츠 트래픽은 Vercel Hobby(비상업·100GB) 초과 가능성 — Cloudflare R2/유료 플랜 검토

**Phase 1이 지키는 약속**(§7): Next.js 앱 구조, 게임=데이터 레코드, iframe 임베드 패턴. 이 세 가지 덕분에 Phase 2는 갈아엎기가 아니라 증축이 된다.

Phase 2 착수 시점: Phase 1 출시 후, 본인 게임 최소 1개가 실제로 올라가고 나서. 착수할 때 별도 브레인스토밍 → 스펙 → 구현 계획을 다시 밟는다.
