# PIXELARIOUS 브랜드 운영 디자인 스펙

작성일: 2026-08-16
상태: 사용자 검토 대기
관련 문서: `docs/superpowers/specs/2026-08-13-neo-kido-design.md` (사이트 디자인 스펙)

## 1. 개요와 목적

PIXELARIOUS는 1인 개발자 LeeDoik이 만든 게임을 브라우저에서 바로 플레이하게 하는 사이트다. 이 문서는 그 사이트 바깥에서 브랜드를 운영하는 방법을 정한다.

목적은 하나다. **여러 소통 창구를 열어 유저 의견을 받는다.** 팔로워 수나 도달은 그 수단이지 목적이 아니다.

- 채널: 인스타그램, 스레드, 유튜브 (세 계정 모두 개설 완료)
- 보조 창구: `pixelarious.online` 사이트 피드백
- 성공 기준
  - 유저 의견이 한곳에 쌓이고, 반영된 결과를 유저가 눈으로 확인할 수 있다
  - 게시물 하나를 만드는 데 드는 시간이 게임 개발을 잡아먹지 않는다
  - 세 채널과 사이트가 같은 브랜드로 보인다

## 2. 브랜드 컨셉

### 2.1 확정 — "아직 다 안 쳐진 이름"

브랜드의 중심 이미지는 **어두운 화면에 켜지는 한 점**이고, 그 위에 깜빡이는 커서가 **아직 쓰는 중**이라는 뜻을 얹는다. 계속 만들어 나가는 1인 개발자의 상태 그 자체가 컨셉이다.

이 컨셉은 상상해서 붙인 것이 아니라 이미 프로젝트 안에 있던 것을 꺼낸 것이다. 근거:

1. **커버 아트 5종이 전부 같은 색 구조를 쓴다.** `src/lib/scenes.ts`의 씬 팔레트에서 `starfall`·`cave`·`pong`·`system`·`lastlogin` 모두 `sky: #0C0A1C`(칠흑) + `hi: #FFEC27`(금색)이다. DMG 팔레트에서도 구조가 같다.
2. **게임 네 개가 같은 이야기를 한다.** 별에서 다음 별로 옮겨 탄다(STARFALL DRIFT), "어두울수록 반짝이는 것이 많아진다"(DOWN THE CAVE), 꺼져 있던 컴퓨터가 부팅된다(LAST LOGIN).
3. **사이트 히어로가 이미 그 장면이다.** `src/components/Hero.tsx`는 어두운 화면에 이름을 한 글자씩 타이핑하고 금색 블록 커서(█)를 1초 간격으로 깜빡인다.
4. **PIX는 PIXELARIOUS의 앞 세 글자다.** 그래서 마크는 약자가 아니라 이름을 치다 멈춘 순간이다. "무슨 약자냐"는 질문이 나오지 않고, 뜻을 물으면 그 답이 곧 브랜드 서사가 된다.

### 2.2 폐기 — "온라인 오락실 운영일지"

초기 검토에서 오락실 컨셉(게임 출시 = 카트리지 입고, 1980년대 미국 오락실 무드)을 유력안으로 잡았으나 폐기한다.

사이트 디자인 스펙 §1이 다음을 핵심 원칙으로 못박고 있다.

> 픽셀/오락실은 사이트 프레임의 컨셉이며, 콘텐츠를 제약하지 않는다. 카트리지에는 픽셀 2D든 Unity 3D든 어떤 게임이든 꽂힌다(게임기 세대교체 서사).

오락실을 브랜드 정체성으로 삼으면 이 원칙과 충돌한다. 아케이드 마크를 달아둔 채로 3D 게임이나 내러티브 게임을 내놓으면 브랜드가 먼저 발목을 잡는다. 오락실은 **사이트 안쪽의 프레임으로만** 남기고, 브랜드 마크와 SNS는 장르에 중립적인 §2.1을 따른다.

같은 이유로 80년대 네온 확장 팔레트(마젠타/시안/브라스)도 폐기한다. 사이트 팔레트를 그대로 쓴다.

## 3. 화자와 톤

화자는 **개발자 LeeDoik 본인**이다. 가상 마스코트나 세계관 화자를 두지 않는다. 유저 의견을 받는 것이 목적인데 화자가 캐릭터면 답이 어색해지고, 1인 운영에서 캐릭터 유지 비용도 크다.

| 채널 | 톤 | 역할 |
|---|---|---|
| 인스타그램 | 공적 | 결과물 쇼케이스. 출시·업데이트·게임 화면 |
| 스레드 | 친근하고 간결하게 | 과정 공유와 대화. 질문, 짧은 개발 메모 |
| 유튜브 | 중립 | 쇼츠 중심 + 게임 출시 시 트레일러 |

언어는 **한/영 병기**다. 본문은 한국어, 핵심 한 줄은 영어를 함께 적는다. 해시태그는 영어권 도달이 큰 `#pixelart` `#indiedev` 계열을 쓴다.

유튜브는 쇼츠(15~60초)를 주력으로 하고 정식 트레일러는 게임 출시 때만 만든다. 데브로그 롱폼은 편집 비용이 개발 시간을 잡아먹으므로 하지 않는다.

## 4. 비주얼 아이덴티티

### 4.1 마크

```
[ 칠흑 배경 ]  PIX█
```

- 구성: 배경 `#0C0A1C`, 흰 글자 `PIX`(Press Start 2P), 금색 블록 커서 `█` `#FFEC27`
- **테두리 프레임 없음.** 프로필은 어차피 원형으로 잘려 사각 프레임이 보이지 않는다. 테두리 폭을 글자에 넘겨 44px에서의 가독성을 확보한다
- 커서는 사이트와 동일하게 **1초 간격 `steps(1)` 깜빡임**. 정지 이미지에서는 켜진 상태로 고정
- CRT 스캔라인 오버레이를 얹는다(검정 20~24%, 3px 반복). 사이트 NIGHT 규칙과 동일
- 파비콘 등 32px 이하에서는 **글자를 빼고 커서 블록만** 남긴다

### 4.2 팔레트

사이트 NIGHT 팔레트를 그대로 쓴다. SNS 전용 색을 따로 만들지 않는다.

| 토큰 | 값 | 용도 |
|---|---|---|
| bg-deep | `#0C0A1C` | 마크·포스트 배경 |
| bg | `#141127` | 보조 배경 |
| surface | `#1D2B53` | 카트리지 박스 |
| text | `#FFF1E8` | 글자 |
| dim | `#8E99D9` | 보조 글자 |
| gold | `#FFEC27` | 커서, 라벨, 강조 |
| accent | `#FF77A8` | 포인트 |
| accent2 | `#29ADFF` | 태그·배지 |

DMG 팔레트는 SNS에서 상시 사용하지 않는다. 팔레트 전환을 소재로 다루는 게시물에서만 등장시킨다.

### 4.3 타이포

사이트와 동일하다. 영문·숫자는 **Press Start 2P**, 한글 본문은 **네오둥근모**. 이미지 안에서도 이 두 폰트만 쓴다.

## 5. 채널별 프로필

핸들은 세 채널 모두 `pixelarious`로 통일한다.

**인스타그램** (공적)

```
PIXELARIOUS
브라우저에서 바로 플레이하는 픽셀 게임을 만듭니다.
Pixel games you can play right in your browser.
1인 개발 · GODOT 4
pixelarious.online
```

**스레드** (친근)

```
PIXELARIOUS
혼자 게임 만듭니다. 만드는 얘기 여기다 써요.
Making pixel games, solo.
pixelarious.online
```

**유튜브 배너**

- 마크 + `PIXELARIOUS` 워드마크 + `브라우저에서 바로 플레이 · PLAY IN YOUR BROWSER`
- 배경은 칠흑 + 픽셀 별. 로고와 문구는 **안전 영역 1546×423 안**에만 배치한다. 바깥은 PC에서만 보이므로 배경만 채운다

> 위 소개글 문안은 초안이며 사용자 확정이 필요하다(§11).

## 6. 포스트 템플릿

네 종을 만들고 **용도로 나눠 쓴다.** 네 종 모두 같은 팔레트·폰트·마크를 쓰므로 피드에서 한 세트로 보인다.

공통 규칙:

- 비율은 **1:1(1080×1080)** 또는 **4:5(1080×1350)**
- **캡션을 이미지 안에 넣지 않는다.** 인스타·스레드는 캡션이 이미지 바깥에 따로 붙는다. 안에 넣으면 같은 말이 두 번 나오고, 이미지 안 글자는 번역도 검색도 되지 않는다
- 이미지 안 글자는 **제목·라벨·질문만**

| 템플릿 | 용도 | 구성 |
|---|---|---|
| **A. 풀블리드** | 게임 화면 쇼케이스 | 게임 화면이 전면. 좌하단에 금색 라벨 + 제목, 우하단에 마크 워터마크 |
| **B. 카트리지** | 출시 공지 | 사이트의 카트리지 배너를 그대로 재현 — 번호·커버·제목·부제·설명·태그 |
| **C. 터미널 로그** | 개발일지·패치노트 | `> BUILD v0.3.1 ... OK` 형식의 로그 몇 줄 + 큰 한글 한 문장 + 커서. **스크린샷 없이도 게시물이 나온다** |
| **D. 질문 카드** | 의견 수집 | `YOUR TURN` 라벨 + 큰 질문 한 줄 + 하단 마크. 배경을 비워 피드에서 눈에 걸리게 한다 |

템플릿 B가 §2.2와 모순되지 않는 이유: 여기서 카트리지는 브랜드 정체성이 아니라 **사이트를 그대로 비추는 장치**다. 포스트에서 본 카트리지를 사이트에서 다시 만나게 하는 것이 목적이고, 카트리지는 사이트 안쪽 프레임으로 이미 존재한다. 마크와 프로필에는 카트리지를 쓰지 않는다.

라벨(금색 배지)은 게시물 종류를 알린다: `NEW GAME` / `DEV LOG` / `YOU ASKED` / `YOUR TURN`.

`YOU ASKED`는 받은 의견을 반영했을 때 쓴다. 의견이 반영되는 것이 보여야 다음 의견이 온다 — 이 라벨이 §1의 목적을 직접 수행한다.

## 7. 제작 방식 — 레포 안에서 렌더한다

이미지를 디자인 툴에서 수작업으로 만들지 않는다. **레포 안에 개발 전용 라우트 `/brand`를 만들고 실제 React 컴포넌트로 렌더한 뒤 PNG로 내보낸다.**

이렇게 하는 이유:

- **드리프트가 원천 차단된다.** 팔레트와 폰트를 `globals.css`의 CSS 변수와 자체 호스팅 woff2에서 그대로 가져오므로, 사이트 색이 바뀌면 브랜드 자산도 같이 바뀐다. 별도 파일에 색을 복사해두면 언젠가 반드시 어긋난다
- **게시물 제작 비용이 가장 낮다.** 템플릿에 텍스트만 갈아끼우면 새 이미지가 나온다. §1의 "게시물 제작이 개발 시간을 잡아먹지 않는다"를 직접 만족한다
- **사이트에 이미 같은 패턴이 있다.** `/editor`가 개발 서버에서만 열리고 배포본에서는 404다(`src/app/editor`). `/brand`도 같은 규칙을 따른다
- 커버 아트 생성 로직(`src/lib/scenes.ts`)을 그대로 재사용할 수 있다

구현 요건:

- `/brand`는 `/editor`와 동일하게 **개발 서버에서만** 열린다. 배포본에서는 404
- 각 자산은 지정 크기 그대로 렌더한다(예: 1080×1080 컨테이너). 화면에서는 축소 표시하되 내보내기는 원본 배율
- 내보내기는 브라우저에서 PNG 다운로드로 처리한다. 별도 서버 렌더링 파이프라인을 두지 않는다
- 산출물은 저장소에 커밋하지 않는다(용량). 필요할 때 다시 렌더한다

## 8. 제작할 파일 규격

| 용도 | 크기 | 메모 |
|---|---|---|
| 프로필 (3채널 공통) | 1024 × 1024 | 원형으로 잘림. 글자를 가장자리에서 충분히 떼기 |
| 유튜브 배너 | 2560 × 1440 | 안전 영역 1546 × 423 안에만 로고·문구 |
| 포스트 (정사각) | 1080 × 1080 | 인스타 피드 기본 |
| 포스트 (세로) | 1080 × 1350 | 피드 점유 면적 최대 |
| 쇼츠 / 릴스 | 1080 × 1920 | 하단 25%는 앱 UI에 가림. 자막을 그 위로 |
| 파비콘 | 32 × 32 | 글자 생략, 커서 블록만 |

모든 래스터 출력은 `image-rendering: pixelated` 기준으로 만든다. 확대 시 보간이 생기지 않도록 정수 배율로 스케일한다.

## 9. 유저 의견 수집

- **SNS 댓글·DM** — 세 채널에서 상시 수집
- **사이트 피드백** — `pixelarious.online`에 피드백 창구를 둔다. 별도 백엔드를 만들지 않고 외부 폼(구글폼 등) 링크로 시작한다
- **반영 공지** — 반영한 의견은 `YOU ASKED` 라벨로 게시한다

디스코드 서버는 만들지 않는다. 팔로워가 모이기 전의 빈 서버는 역효과다. 이후 재검토한다.

## 10. 범위 밖 (YAGNI)

- 디스코드 서버
- 가상 마스코트·세계관 화자
- 데브로그 롱폼 영상
- SNS 전용 확장 팔레트
- 자체 피드백 백엔드
- 게시 자동화·예약 도구

## 11. 미해결 항목

사용자 확정이 필요하다.

1. **소개글 문안** — §5의 세 문안은 초안이다
2. **핸들 확보 여부** — 세 채널에서 `pixelarious`를 실제로 쓸 수 있는지 확인 필요
3. **게시 빈도** — 주 몇 회로 운영할지 정하지 않았다
4. **도메인 연결 상태** — `pixelarious.online` 연결이 완료되었는지 확인 후 프로필 링크에 반영
