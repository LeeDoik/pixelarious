# LAST LOGIN — 데스크톱 조작형 퍼즐 확장

날짜: 2026-08-22
상태: 승인됨 (브레인스토밍 — 세 갈래 전부, B→A→C 순서, 기록물 9→12)
전제: 세계관·인물 설정집(2026-08-19), 2003년 1월의 침입자(2026-08-21)

## 0. 한 줄

암호 입력에 몰려 있던 퍼즐 문법을 OS 동작 자체로 넓힌다 — 숨긴 것을 드러내고,
두 창을 맞대고, 열을 켜서 정렬하고, 파일을 끌어다 놓는다.

## 1. 왜

현행 퍼즐 넷의 메커니즘은 이렇다.

| | 앱 | 조작 |
|---|---|---|
| 퍼즐1 | 탐색기 | 폴더 암호 입력 |
| 퍼즐2 | 메일 | zip 암호 입력 |
| 퍼즐3 | 브라우저 | 주소 직접 타이핑 |
| 퍼즐4 | 휴지통 | 올바른 파일 복원 |

**넷 중 셋이 "정답 문자열을 어딘가 친다"이고, OS 동작이 답인 것은 퍼즐4 하나뿐이다.**
누리OS 2002는 창·목록·열·휴지통·즐겨찾기를 다 갖춘 껍데기인데 그 껍데기가
퍼즐 문법으로 쓰이는 자리가 하나밖에 없다. 이 확장은 새 앱을 만들지 않고
**기존 다섯 앱의 조작만으로** 문법 넷을 더 만든다.

서사적으로는 관계도에서 가장 비어 있던 자리를 채운다. 성진에게 들어오는 화살표는
전부 도착하는데 그가 내보내는 화살표는 조 소견서 하나뿐이고, 그 문서가 게임에 없다.
이 사슬의 두 번째 칸이 그것이다.

## 2. 비목표

- 새 앱을 만들지 않는다 (제어판·계산기·찾기·미디어 플레이어 전부 제외)
- 우클릭 속성 대화상자를 만들지 않는다 — 액세스 날짜를 열로 보여주면 필요 없다 (YAGNI)
- 기존 퍼즐 1~4를 고치지 않는다. 이미 배포됐고 회귀 테스트가 지키고 있다
- 성진의 생사를 확정하지 않는다. 15세 수위·얼굴 없음·실존 단체 비특정 전부 유지

## 3. 사슬

병렬로 놓지 않는다. 각 칸이 다음 칸의 재료를 낳는다.

```
퍼즐5  숨긴 파일 보기        →  '성진이만' 폴더에 그릇기록.txt가 있었다
       (탐색기 보기 메뉴)        성진이 자기에 대해 쓴 문서

퍼즐6  두 창 대조            →  사본과 손글씨 제출본이 다르다
       (사진 ↔ 텍스트)          지운 한 문단이 소견서였다

퍼즐7  액세스한 날짜 열      →  그날 새벽 관리자가 무엇을 열었는가
       (열 켜기 + 정렬)          그리고 점검표에 안 적은 것이 하나 있다

퍼즐8  관문 캐시 2판         →  폐쇄 뒤에 숫자가 바뀌었다
       (2002-11 ↔ 2003-01)      쉬어가는 중 넷이 줄고 비움 완료 셋이 늘었다

시스템 끌어놓기 진술서       →  이 넷을 경찰에 넘길 것인가
       (종반 폴더)               넣은 것과 뺀 것이 엔딩을 쓴다
```

문법이 다섯 다 다르고, 현행 넷과도 겹치지 않는다.

## 4. 퍼즐5 — 숨긴 파일

### 4.1 자산

`fs.json`에 노드 하나. `'성진이만'` 폴더(id `locked`, 퍼즐1 뒤에 열림) 안.

```json
{"id": "l_bowl", "parent": "locked", "name": "그릇기록_0803.txt",
 "type": "doc", "cid": "doc:bowl_record", "hidden": true, "record": true,
 "size": 1136, "mtime": "2002-08-03 23:41", "atime": "2002-11-01 03:52"}
```

`doc:bowl_record` 본문 — 8월 수련회 셋째 날 밤에 쓴 자기비판 문서. 필사가 교단의
말을 옮겨 적는 것이라면 이것은 **자기를 옮겨 적는 것**이다. 문체는 성진 초기체
(짧은 문장, `<< >>` 자기 검열 괄호, 마지막에 한 발 물러섬).

분량은 기존 문서와 같은 급(700~900자)으로 맞춘다. 마지막 문단이 **없다** —
그 자리가 퍼즐6이다.

### 4.2 게이트 신호 세 겹

1. **텍스트 단서 (주된 것).** 같은 폴더의 `기억나는대로.txt`(`doc:evidence_memo`)에
   한 줄 추가:
   ```
   8월에 쓴 건 따로 뒀다. 보이면 안 되니까 안 보이게 해놨다.
   ```
   성진은 겁이 많아 두 군데 적는 사람이고, 플레이어는 이미 그 습관으로 퍼즐4를 풀었다.
2. **개수 불일치 (확인용).** 탐색기 상태표시줄이 `개체 6개`인데 목록엔 5개.
   `_refresh()`의 `entries.size()`가 숨김 포함 개수를 쓰도록 한다.
   현실의 윈도우는 이렇게 세지 않지만, **누리OS는 센다** — 이 게임에서 상태표시줄이
   목록보다 많이 아는 유일한 자리이고, 그것이 단서다.
3. **교차 확인.** 회수확인.txt의 `'성진이만' 폴더 잠김. 열지 못함.` —
   관리자도 이걸 못 봤다.

### 4.3 조작

도구모음 **보기** 버튼을 드롭다운으로 승격한다. 지금은 아이콘/자세히 토글 두 버튼이다.

```
보기 ▾
  ● 큰 아이콘
  ○ 자세히
  ─────────────
  ☐ 숨긴 파일 보기
  ☐ 액세스한 날짜 열      ← 퍼즐7에서 켜진다
```

메뉴 막대(파일·편집·보기·도움말)는 만들지 않는다 — 크롬 수준 "중간" 원칙
(도구모음 + 주소줄 + 상태표시줄)을 유지한다. 이 원칙은 메일·브라우저가 이미 따르고 있다.

체크 상태는 탐색기 인스턴스가 아니라 `GameState` 플래그로 보관한다
(`view_hidden`, `view_atime`). 창을 닫았다 열어도 유지돼야 하고, 휴지통도 같은 목록
위젯을 쓰기 때문이다.

### 4.4 판정

숨긴 파일 보기를 켜고 `그릇기록_0803.txt`를 연다 → `mark_read("doc:bowl_record")`,
플래그 `bowl_record_found`.

**켜는 것만으로는 성립하지 않는다.** 여는 것이 판정이다 — 이 게임의 다른 퍼즐도
전부 "읽었는가"로 끝난다.

### 4.5 힌트 3단 (슬기)

1. `오빠는 겁이 많아서 뭐든 두 군데에 적어요. 한 군데는 벌써 찾으셨잖아요.`
2. `그 폴더에 파일이 다섯 개 맞아요? 오빠가 안 보이게 해놓는 법 알았어요. 예전에 저한테 자랑했거든요.`
3. `탐색기 보기 메뉴에 숨긴 파일 보기가 있어요. 그거 켜보세요.`

게이트는 `'성진이만'` 폴더를 열람 중이고 `bowl_record_found`가 아직 없는 동안 활성.

### 4.6 실패 모드

보기 드롭다운을 아예 안 여는 경우. 완화 셋: ①보기 버튼은 퍼즐 이전부터 자세히 보기
전환에 쓰이므로 이미 눌러본 버튼이다 ②상태표시줄 숫자가 폴더를 열 때마다 보인다
③힌트 3단이 명시한다.

## 5. 퍼즐6 — 두 창 대조

### 5.1 자산

`새빛수련회` 폴더에 손글씨 사진 하나 추가. 필사 제출본 셋과 나란히 놓여서,
사본을 찾기 전에는 넷째 필사로 스쳐 지나간다.

```json
{"id": "s_photo4", "parent": "saebit", "name": "그릇기록_제출본.jpg",
 "type": "image", "cid": "img:bowl_record_photo", "record": true,
 "image": "res://assets/img/photos/bowl_record.png",
 "size": 271104, "mtime": "2002-08-03 23:52", "atime": "2002-11-01 03:52"}
```

아트는 `scripts/gen_pilsa_photos.py`를 재사용해 생성한다 (같은 종이·같은 필체·같은
조명, 지장 없음 — 지장은 서원문에만 찍는다).

### 5.2 무엇이 다른가

제출본 마지막 문단이 사본에는 없다.

```
○○ 님은 아직 어머니 얘기를 못 꺼내십니다.
조금 더 기다리면 될 것 같습니다.
```

**그릇기록과 조 소견서가 같은 종이였다.** 자기에 대해 쓰는 칸 아래에 남에 대해 쓰는
칸이 있었고, 성진은 자기 사본에서 그 부분만 지웠다. 지웠다는 것이 그가 알고 있었다는
증거다.

세계관 §10 우선순위 1(성진이 쓴 조 소견)과 우선순위 3(그릇 기록)을 한 문서로 합친
것이다. 문서를 둘로 쪼개면 소견서가 고발장처럼 읽히는데, 자기비판 문서의 꼬리로
붙이면 **선의로 쓰인 관찰 기록**이 된다. 악의가 없어야 무섭다는 §1.4 수위 주의를
구조로 지킨다.

`○○`는 이니셜도 이름도 주지 않는다. 성진이 그 사람 이름을 기억하지 못한다는 것이
내용이다 (`기억나는대로.txt`의 "8월에 같이 갔던 신입 중 두 명은 9월부터 안 보인다"와
같은 사람일 수 있으나 확정하지 않는다).

### 5.3 조작

사진 창에 확대(1x ↔ 2x) 를 넣고, 확대 상태에서 마지막 문단 영역을 클릭한다.

- **사본 창이 같이 떠 있으면** → 확정. 대화상자:
  `이 문단은 사본에 없다. 성진은 제출하고 나서 자기 것에서만 지웠다.`
- **안 떠 있으면** → 방향 안내. `이 문단이 낯설다. 사본에는 이런 게 있었나.`
  실패해도 다음 행동을 알려준다.

"두 창을 나란히"를 강제하지 않고 **보상**한다. 강제는 창 배치 짜증으로 돌아온다.

### 5.4 판정

플래그 `bowl_diff_found`, `mark_read("img:bowl_record_photo")`.
슬기 대화 분기 하나 (오빠가 남에 대해 쓴 것을 동생이 읽는 장면 — 설정집이 요구하던
그 장면이다. 슬기는 오빠를 변호하지 않는다. `…오빠가 그런 걸 왜 써요.` 한 줄 뒤에
멈춘다).

### 5.5 힌트 3단

1. `오빠는 뭐든 두 번 써요. 손으로 한 번, 컴퓨터로 한 번. 그럼 둘이 같아야 하는 거 아니에요?`
2. `사진이랑 파일이랑 같이 띄워놓고 보세요. 마지막 쪽에 뭐가 더 있는 것 같은데.`
3. `제출본 마지막 문단이요. 그거 사본에는 없어요. 오빠가 지운 거예요.`

## 6. 퍼즐7 — 액세스한 날짜

### 6.1 메커니즘

`fs.json` 전 노드에 `atime` 추가. 대부분 2002-11-02 이전이고, 관리자가 그날 새벽
연 것만 `2003-01-31 04:0x`다.

| 노드 | atime | 무엇을 증명하나 |
|---|---|---|
| `t2` `t3` `t4` 손상 백업 | 04:07 / 04:10 / 04:13 | 삭제는 2002년 성진이 했는데 **열린 건 2003년** — 왜 손상됐는지가 확정된다 |
| `t1` backup_1102 | 04:14 | 열려다 실패. "다른 프로그램이 사용 중" |
| `t6` 회수확인 | 04:16 | 쓰고 지운 시각과 같다 |
| `locked` 폴더와 그 안 전부 | 2002-11-01 | **그가 못 열었다.** 잠금이 증거를 지킨 것이 날짜로 보인다 |
| `p_family` 가족사진_2001설.jpg | 04:09 | **점검표에 이 항목이 없다** |

`p_family`가 이 퍼즐의 심장이다. 회수확인.txt는 본체·통장 사본·입금 기록·백업·
방명록·처리 여섯 항목을 적었고 사진은 한 글자도 없다. 그는 사진을 열어봤고,
그것을 보고하지 않았다. **이유는 끝까지 적지 않는다.**

기존 콘텐츠와 어긋나지 않는지 전수 대조가 필요하다 — 회수확인.txt가 말한 것과
atime이 말하는 것이 정확히 겹쳐야 하고, 딱 하나(가족사진)만 어긋나야 한다.

### 6.2 조작

보기 ▾ → `☑ 액세스한 날짜 열` → 자세히 보기에 5번째 열이 붙는다 → 열 머리글을
눌러 정렬 → 04시대 무리가 뭉친다 → 그중 가족사진을 연다.

`Tree`의 열 정렬은 Godot이 기본 제공하지 않으므로 머리글 클릭 → `entries` 정렬 후
`_fill_details()` 재호출로 구현한다. 정렬 상태(열·방향)도 `GameState` 플래그가 아니라
탐색기 인스턴스 변수로 둔다 — 창을 닫으면 풀려도 되는 종류다.

### 6.3 판정

**정렬했는가가 아니라 가족사진을 열었는가.** 정렬은 발견 수단이다.
플래그 `unlogged_access`. 기록물은 늘지 않는다 (새 문서가 생기지 않으므로).

게이트는 `intruder_found` 이후 활성. 회수확인.txt를 아직 못 찾은 플레이어에게는
이 퍼즐이 존재하지 않는다 — 점검표를 읽어야 "그가 무엇을 열었나"라는 질문이 생긴다.

### 6.4 힌트 3단

1. `그 사람이 뭘 봤는지 알 수 있을까요. 컴퓨터는 열어본 것도 남는다던데.`
2. `탐색기 보기 메뉴요. 날짜 종류가 하나가 아니에요.`
3. `액세스한 날짜 열을 켜고 그걸로 정렬해 보세요. 1월 31일 새벽 것만 위로 모여요.`

### 6.5 슬기 분기

```
슬기: 사진은 왜 열어봤을까요.
슬기: 점검표에는 없잖아요. 안 적었다는 건 시켜서 한 게 아니라는 거고요.
슬기: …그 사람도 사람이었나 봐요. 그게 더 싫어요.
```

## 7. 퍼즐8 — 관문 캐시 2판

### 7.1 메커니즘

브라우저 상태표시줄은 이미 본문에서 정규식으로 캐시 저장 시각을 뽑아 보여준다.
`/saebit/gate`에만 판본 두 개를 두고, 상태표시줄에 다른 판 링크를 붙인다.

```
저장: 2002-11-02 23:39   · 다른 판 1개 ▸
```

**퍼즐3이 여는 기본 판은 2002-11-02 그대로 둔다.** 퍼즐 1~4 무변경 원칙을 지키고,
"2003-01-31 캐시는 정확히 N개"라는 침입자 층의 교차 일치 테스트도 살아 있게 하기
위해서다 (N은 2 → 3으로 갱신한다, §12·§13).

`web.json`의 `pages`에 키 하나 추가 (`cafe.nurinet.co.kr/saebit/gate@2003-01-31`).
주소창으로는 갈 수 없고 상태표시줄 링크로만 열린다 — 퍼즐3의 "링크되지 않는 주소"
규칙을 깨지 않기 위해서다. 캐시 버저닝 시스템은 만들지 않는다. **페이지 두 개면 된다.**

발견은 "이 주소에 판본이 두 개 있다"이고, 그 자체가 정보다 — 성진이 저장한 뒤에
누군가 같은 주소를 한 번 더 열었다는 뜻이므로.

### 7.1.1 회수확인.txt 한 줄 추가

교차 일치를 유지하려면 점검표가 이 접속을 알고 있어야 한다. 방명록 항목 앞에 한 줄:

```
※ 관문 — 접속 확인. 명단은 정리했음.
```

`명단은 정리했음`이 2003-01판에서 11월 이동 예정자 항목이 사라진 이유가 된다.
관리자 지시문의 `※` 문체를 그대로 쓴다.

### 7.2 무엇이 바뀌었나

| | 2002-11-02 23:39 | 2003-01-31 04:11 |
|---|---|---|
| 정회원 | 47 | 51 |
| 쉬어가는 중 | 6 | **2** |
| 비움 완료 | 3 | **6** |
| 11월 이동 예정자 | 김○숙 · 한○진 · 정○우 | (항목 삭제) |
| 자료실 | 이탈자 응대 지침 **3판** | **4판** |
| 인도자 공지 | 기계 안의 일은 기계를 아는 사람이 다 봅니다 | 본 관문의 접속 기록은 정기적으로 정리됩니다 |

쉬어가는 중 넷이 줄고 비움 완료 셋이 늘었다. **성진이 그 셋에 들어 있는지는
말하지 않는다** — 이동 예정자 항목이 통째로 사라졌으므로 대조할 수단도 없다.
생사 미확정 규칙을 지키면서 낼 수 있는 최대 무게다.

`이탈자 응대 지침`이 3판에서 4판이 된 것은 제목만 바뀐다. 여전히 열리지 않는다.
열리지 않는 편이 무섭다는 §10 판단을 유지한다.

### 7.3 조작·판정

두 판을 창 두 개로 열고, 바뀐 숫자(회원 현황 블록)를 클릭. 퍼즐6과 같은 대조 문법이고,
같은 "상대 창이 떠 있으면 확정" 규칙을 쓴다.

플래그 `gate_diff_found`, `mark_read("web:cafe_gate_2003")`.

### 7.4 힌트 3단

1. `그 관문 페이지 아래에 저장한 날짜 있잖아요. 오빠가 저장한 건 11월 2일이에요.`
2. `페이지 아래 저장한 날짜 옆에 판이 하나 더 있다고 떠요. 그것도 열어보세요.`

## 8. 시스템 — 끌어놓기 진술서

### 8.1 언제

종반 허브(`g4l`·`g4m`·`iq4`)에서 `인쇄해서 경찰에 가세요`를 고른 직후.
지금은 `g5a`로 바로 가는데, 그 사이에 장면 하나를 끼운다.

```
슬기: 제가 내일 아침에 갈게요.
슬기: 근데 뭘 가져가야 할지 모르겠어요. 골라주세요.
```

`원본 그대로 보내드릴게요`(`g5b`) 쪽은 손대지 않는다. **고르는 쪽과 전부 넘기는 쪽**,
두 엔딩의 차이가 여기서 처음으로 생긴다.

### 8.2 무엇

바탕화면에 `경찰 제출` 폴더 아이콘이 생긴다. 탐색기·휴지통·메일·브라우저에서 항목을
끌어다 놓는다. 폴더를 열면 넣은 목록이 보이고, 거기서 빼기도 된다.
다 골랐으면 폴더 안 `인쇄` 버튼.

**정답이 없다.** 최소 개수를 강제하지 않는다. 빈 폴더로 인쇄하는 것도 유효한 선택이다.

### 8.3 엔딩 조립

조합 폭발을 막기 위해 항목마다 태그를 붙이고, 조합이 아니라 **규칙을 순서대로
평가해 문단을 쌓는다.** 최종 3~4문단.

| 태그 | 항목 | 넣으면 |
|---|---|---|
| `money` | 입금내역 · 빚 정리 · 생활비 정리 | 돈 문제로 접수된다 |
| `coercion` | 회계 3차 · 인도자 메일 2통 · 탈퇴하려면 | 수사가 시작된다 |
| `intruder` | 회수확인 · 관문 2003판 | 실종 이후로 사건이 넓어진다 |
| `identity` | 서원문 · 필사 · 그릇기록(사본·제출본) | 성진이 어떤 사람이었는지가 조서에 남는다 |
| `private` | 부치지 못한 편지 · 유서 · 미니홈피 비밀글 | 슬기가 그걸 읽게 된다 — 별도 문단 |

평가 순서:

1. 아무것도 없으면 → `…그냥 제가 알아서 할게요.` 이후 문단 없음
2. `money`만 → 돈 문단
3. `money` + `coercion` → 수사 문단으로 대체
4. `intruder` 있으면 → 실종 문단 추가
5. `identity` 있으면 → 조서 문단 추가
6. `private` 있으면 → 마지막에 슬기 문단 추가 (넣든 안 넣든 판단하지 않는다)

태그는 `fs.json`이 아니라 별도 `content/evidence_tags.json`에 둔다. 파일 목록과
증거 분류는 다른 관심사이고, 태그가 fs에 섞이면 탐색기 코드가 서사를 알게 된다.

### 8.4 왜 이게 퍼즐이 아니라 시스템인가

앞의 넷은 "찾았는가"를 묻는다. 이것은 **"무엇을 남길 것인가"**를 묻는다.
정답 판정이 없고 실패도 없다. 그래서 마지막에 온다.

## 9. 기록물 9 → 12

```json
{"records": [
  "doc:essay_2001", "img:family_photo", "doc:donation_ledger",
  "chatlog:2002-10-05", "doc:doctrine_2", "mail:m_demand_3",
  "web:cafe_gate", "web:myhome_secret", "doc:diary_final",
  "doc:bowl_record", "img:bowl_record_photo", "web:cafe_gate_2003"
]}
```

- 메신저 상단 표시줄은 자동으로 `오빠가 남긴 것 · N/12`가 된다 (분모가 `records().size()`)
- `EndingScene.should_show_hidden()`은 코드 변경 없음 — 같은 식이 12를 센다
- **회수확인.txt는 기록물에 넣지 않는다.** 침입자 층의 "플래그만 바꾼다" 성질 유지

### 9.1 기존 세이브

`records_count()`는 저장된 `_read` 딕셔너리를 센다. 9/9를 채운 세이브는 9/12로
보이고, 새 셋을 읽으면 12/12가 된다. **마이그레이션 코드는 넣지 않는다** —
늘어난 셋은 그 세계에 원래 있던 것이고, 이어서 찾으면 되는 상태가 맞다.
숨은 엔딩을 이미 본 플레이어가 다시 못 보는 것은 아니다 (엔딩은 매번 판정한다).

### 9.2 라벨

`오빠가 남긴 것`이라는 라벨에 `web:cafe_gate_2003`(교단이 남긴 것)이 들어가는 것은
이미 기존 9개의 `mail:m_demand_3`·`web:cafe_gate`가 같은 성격이므로 새로 생기는
불일치가 아니다. 라벨은 "오빠의 컴퓨터에 남은 것"으로 느슨하게 읽힌다. 바꾸지 않는다.

### 10.2 M9 — 조작형 퍼즐의 힌트

`puzzles.json`은 지금 `{answer, hints[3]}` 형태이고 `try_answer()`가 문자열을 맞춘다.
조작형은 정답 문자열이 없으므로 `kind` 필드를 추가한다.

```json
"hidden_file": {
  "kind": "action",
  "hints": ["…", "…", "…"]
}
```

`kind: "action"`인 퍼즐은 `try_answer()`를 타지 않고, 앱 코드가 직접
`GameState.set_flag()`을 부른다. `HintEngine`은 변경 없음 — `set_gate(puzzle_id)`가
문자열만 받으므로 그대로 쓴다. 각 앱이 자기 게이트 진입/이탈에서 `set_gate`를 부른다.

게이트 활성 조건:

| 퍼즐 | 활성 | 해제 |
|---|---|---|
| `hidden_file` | `locked` 폴더 열람 중 | `bowl_record_found` |
| `bowl_diff` | `bowl_record_found` 있고 사진 또는 사본 창이 떠 있음 | `bowl_diff_found` |
| `access_column` | `intruder_found` 있고 탐색기가 떠 있음 | `unlogged_access` |
| `gate_two` | `/saebit/gate` 열람 중 | `gate_diff_found` |

`gate_two`만 `intruder_found`를 요구하지 않는다. 요구하면 기록물 12/12가 침입자 층에
묶여서, 지금은 "한 줄 더"일 뿐인 `intruder_found`가 숨은 엔딩의 필수 조건이 된다.
침입자 층은 계속 선택적인 층으로 둔다.

### 10.3 M7 — 창 사이 드래그앤드롭 (가장 무거운 것)

Godot Control의 `_get_drag_data` / `_can_drop_data` / `_drop_data`를 쓴다.
창은 전부 `WindowManager` 아래 같은 트리에 있으므로 창 경계를 넘는 드래그는
엔진이 기본 지원한다. 확인할 것:

- 드래그 중 창 포커스 전환 — 드롭 대상 창이 뒤에 있으면 못 놓는다.
  `WindowManager`에 "드래그 중 호버한 창을 앞으로" 규칙을 넣는다.
- 드래그 프리뷰(파일 아이콘+이름)를 각 앱이 같은 모양으로 만들어야 한다 →
  `OSDialog`처럼 공용 헬퍼로 뽑는다.
- CRT 곡면 좌표 역보정이 드래그 좌표에도 걸리는지 확인 — 히트테스트에서 한 번
  물린 적이 있다(창 시스템 히트테스트 연쇄 버그).

## 15. 리스크

1. **창 사이 드래그앤드롭 (M7)** — 이 스펙에서 유일하게 검증 안 된 기반 기능이다.
   CRT 곡면 좌표 역보정과 창 히트테스트가 이미 한 번 물린 적 있는 자리와 겹친다.
   단계 5를 마지막에 둔 것도 이 때문이다. 여기서 막히면 앞 넷은 이미 배포돼 있다.
2. **기록물 9 → 12** — 배포된 세이브의 카운터가 9/12로 보인다. 의도된 동작이지만
   플레이어에게는 "왜 갑자기 줄었지"로 읽힐 수 있다. 슬기 대사로 흡수할 여지를
   단계 6에서 검토한다.
3. **대조 퍼즐이 얕아질 위험** — "틀린 그림 찾기"가 되면 이 게임의 결이 깨진다.
   기준: 다른 한 줄이 **서사를 나르지 못하면 넣지 않는다.** 퍼즐6은 *성진이
   가담자였다*를, 퍼즐8은 *넷이 사라졌다*를 나른다.
4. **`atime` 전수 추가의 일관성** — 노드가 30개 남짓이고 기존 `mtime`·회수확인
   본문과 전부 맞아야 한다. 손으로 넣으면 어긋난다. 스크립트로 생성하고 테스트로 잠근다.
